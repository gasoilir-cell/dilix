# خط‌لولهٔ i18n موبایل

`lib/l10n/translations.dart` **تولیدشده** است؛ دستی ویرایشش نکن. این پوشه
بازتولیدش می‌کند.

## مدل

لایهٔ ترجمه سبکِ gettext است: **خودِ متنِ فارسی کلید است** (`lib/core/l10n.dart`).
پس افزودنِ رشتهٔ تازه به UI یعنی فقط `tr('متنِ فارسی')` — نه کلیدِ نمادین، نه
دست‌زدن به جدول. فارسی هیچ جدولی لازم ندارد چون fallbackِ `tr` خودِ کلید است.

## مراحل

همهٔ فرآورده‌های میانی در `tool/i18n/data/` می‌نشینند. **نامِ `build/` را به کار
نبر**: `.gitignore`ِ فلاتر الگوی `build/` را در هر عمقی می‌گیرد و فرآورده‌ها
بی‌صدا از مخزن حذف می‌شوند.

```bash
cd frontend/mobile

# ۱) استخراجِ رشته‌های مبدأ از سورس  →  data/sources.json
python3 tool/i18n/extract.py

# ۲) استخراجِ دیکشنریِ حرفه‌ایِ اپِ وب  →  data/web_dict.json
#    (شیءِ DICT در src/lib/i18n.ts اپِ وب؛ پویشگرِ نویسه‌به‌نویسهٔ TS)
#    مسیر آرگومانِ موقعیتی است، نه --src؛ با سوییچِ اشتباه اسکریپت خطا می‌دهد
#    ولی `web_dict.json`ِ کهنه سرِ جایش می‌مانَد و بقیهٔ خط‌لوله بی‌صدا با
#    دیکشنریِ قدیمی جلو می‌رود.
python3 tool/i18n/web_extract.py ../web/src/lib/i18n.ts

# ۳) تطبیقِ املاییِ موبایل با دیکشنریِ وب  →  data/web_hits.json
python3 tool/i18n/web_dict.py

# ۴) تقسیمِ کار بینِ حالتِ ساده و زمینه‌دار  →  data/jobs_*.json
python3 tool/i18n/plan.py

# ۵) قالبِ اصطلاحاتِ نقاب‌دار (برند/دامنه)  →  data/jobs_terms.json
python3 tool/i18n/terms.py

# ۶) ترجمه — فقط روی سرور، چون کانتینر شبکهٔ بیرونی ندارد
scp tool/i18n/translate.py tool/i18n/data/jobs_*.json server:/tmp/
ssh server 'python3 /tmp/translate.py --jobs /tmp/jobs_plain.json  --out /tmp/mt_plain.json'
ssh server 'python3 /tmp/translate.py --jobs /tmp/jobs_primed.json --out /tmp/mt_primed.json --primed'
ssh server 'python3 /tmp/translate.py --jobs /tmp/jobs_terms.json  --out /tmp/mt_terms.json'
scp server:/tmp/mt_*.json tool/i18n/data/

# ۷) تولیدِ فایلِ Dart
python3 tool/i18n/generate.py

# ۸) ممیزیِ کیفیتِ جدولِ تولیدشده
python3 tool/i18n/sanity.py > tool/i18n/data/sanity.txt
```

## نقابِ اصطلاح (`{9}`)

مترجمِ ماشینی «دیلیکس» را Deluxe، «ریل» را Schienen/القضبان و «امانت» را
Amanat می‌داد. راه‌حل: پیش از ترجمه واژهٔ دامنه با جای‌نگهدارِ `{9}` پوشانده
می‌شود، قالبِ بی‌واژه ترجمه می‌شود و بعد اصطلاحِ درستِ هر زبان از جدولِ `TERMS`
در `curated.py` جایش می‌نشیند. برای زبانِ چینی فاصله‌های زائدِ کنارِ جای‌نگهدار
جمع می‌شوند، چون خطِ چینی فاصلهٔ واژگانی ندارد.

## چرا دو حالتِ ترجمه

مترجمِ ماشینی برای برچسبِ تک‌واژه‌ای زمینه ندارد: «انصراف» را `opt out`
می‌دهد نه `Cancel`، و «ذخیره» را در آلمانی `sparen` (پول‌اندوزی) می‌دهد نه
`Speichern`. حالتِ زمینه‌دار متن را با پیشوندِ «دکمهٔ برنامه: » می‌فرستد و
پیشوندِ ترجمه‌شده را تا نخستین دونقطه می‌بُرد. جمله‌های بلند این را لازم ندارند.

## نگهداری

- اصلاحِ دستیِ یک ترجمه → در `curated.py` بگذار، نه در فایلِ تولیدی.
- تطبیق با دیکشنریِ وب عمداً **فقط املایی** است (نیم‌فاصله/کسره/فاصله)، نه
  تقریبی: «ثبت‌نشده» و «ثبت‌شده» ۹۳٪ شبیه‌اند و تطبیقِ تقریبی معنا را وارونه
  می‌کند.
- اگر جای‌نگهدارِ `{0}` در ترجمه گم شود، آن ورودی دور انداخته می‌شود و متنِ
  فارسی سرِ جایش می‌مانَد — پارامترِ ناپدیدشده بدتر از زبانِ ترجمه‌نشده است.
- مترجم `\n` را بی‌سروصدا می‌خورَد، پس رشتهٔ چندخطی **خط‌به‌خط** ترجمه و دوباره
  به هم چسبانده می‌شود؛ `sanity.py` نشانگرِ `newline-lost` را دائمی چک می‌کند.
- `tr()` تابع است، نه ثابتِ زمانِ کامپایل: در `static const` و مقدارِ پیش‌فرضِ
  پارامتر جا نمی‌گیرد. به‌جایش getter بگذار یا پارامتر را nullable کن و در بدنه
  `?? tr('…')` بنویس.
- ویجتی که زبان را از `PreferencesScope` نمی‌خوانَد با تعویضِ زبان دوباره ساخته
  نمی‌شود — به‌ویژه وقتی والد آن را با نمونهٔ `const` می‌سازد. نمونه‌اش
  `HomeShell` است که به همین دلیل زبانِ جاری را صریح می‌خوانَد.

## ممیزیِ نشت

`python3 tool/i18n/audit.py` هر رشتهٔ فارسیِ کاربر-محور را که از `tr()`
نمی‌گذرد گزارش می‌کند. «سیم‌کشی‌شده» یعنی بی‌نشت نیست.
